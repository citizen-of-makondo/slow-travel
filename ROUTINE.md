# Инструкция для рутины автообновления

Задание для запланированного агента. Запускается раз в сутки, обновляет туры из
Telegram и журнал из Threads. Агент правит **только `data/*.json`** — разметку
собирает `scripts/build.mjs`.

## 0. Правила, которые важнее всего

- **Всё едет прямо в `main`.** Никаких веток и pull request'ов: закончил, собрал,
  проверил — коммит и пуш. Страховка не в ревью, а в валидации сборщика и в том,
  что любой коммит откатывается одной командой.
- **Туры живут в постах-анонсах.** Каждый тур — это отдельный пост канала, где есть
  дата, программа, цена и приглашение записаться. Именно из них берутся новые туры.
- **Пост «Информация по местам» — не обязателен.** Когда он есть, он главный по
  свободным местам. Когда его нет — это не ошибка и не повод ничего не делать:
  туры всё равно добавляются из анонсов, просто статусы мест не обновляются.
- **Не выдумывать данные.** Нет числа мест — оставить прежнее значение. Не понял,
  тур это или рассказ, — не трогать и написать в отчёте.

## 1. Туры

### 1.1. Собрать канал

Скачать `https://t.me/s/slowtour` (обычный HTTP, без авторизации). Пагинация назад —
`?before=<id>`. Достаточно уйти назад до самого раннего тура, который уже есть в
`data/tours.json`: глубже смотреть незачем.

### 1.2. Найти анонсы туров

Пост — анонс тура, если в нём есть **все четыре** признака:

1. конкретная дата или диапазон дат поездки;
2. программа — что увидим, куда заедем (обычно списком с `🔸`);
3. цена: `💰`, «евро», `€`, «Стоимость», «Цена»;
4. приглашение записаться: «зовём вас с собой», «Записаться», `@lbuzunova`.

Нет цены и записи — **не тур**. Рассказы про сыр, споменики, диких коней, визовые
новости, пожары и закрытые мосты туром не являются, даже если там есть даты.

Пример настоящего анонса: `t.me/slowtour/2501` (Ковачица и Вршац),
`t.me/slowtour/2516` (Сента).

### 1.3. Добавить новые

Сверить найденные анонсы с `data/tours.json` по полю `post`. Анонса нет в файле —
добавить запись:

| Поле | Чем заполнять |
|------|---------------|
| `slug` | латиницей, kebab-case, по месту: `senta`, `kovacica-vrsac`. Стабильный: у существующих туров не менять никогда |
| `title` | направление так, как назвали бы люди: «Сента, Сербия», «Марокко» |
| `dates` | по-человечески: «24 октября · один день», «17 — 20 сентября». Тире — символ `—` |
| `endsOn` | `YYYY-MM-DD`, последний день тура. По нему сортируется расписание и вычисляются прошедшие туры |
| `price` | коротко: `110 €`. Только число и знак валюты, без «/чел.» и без слова «евро» |
| `summary` | 1–2 предложения, до 200 знаков, своими словами, без эмодзи. Самое интересное из программы, а не пересказ всего |
| `status`, `statusLabel` | см. 1.4 |
| `post` | ссылка на сам анонс: `https://t.me/slowtour/<id>` |
| `photo`, `photoAlt` | см. 1.5 |

Порядок записей в файле неважен — сборщик сортирует туры по `endsOn`.

Если анонсов вдруг нашлось больше десятка — это ошибка разбора. Ничего не менять,
написать в отчёте.

### 1.4. Статусы мест

Приоритет источников, сверху вниз:

1. **Пост «Информация по местам»**, если он есть в канале. Он главный: перекрывает
   всё остальное для перечисленных в нём туров.
2. **Текст самого анонса**, если в нём прямо сказано про места («мест нет»,
   «осталось 2 места»).
3. **Ничего из этого нет** → для нового тура `status: "open"`,
   `statusLabel: "Идёт запись"`. Это честно: запись открыта, а сколько мест —
   мы не знаем. Придумывать «Есть места» нельзя.

Для тура, который уже есть на сайте, при отсутствии данных статус **не трогать**.

| `status` | Когда | `statusLabel` |
|----------|-------|---------------|
| `open` | места есть либо неизвестно | «Есть места» / «Идёт запись» |
| `few` | названо конкретное число | «Осталось N мест» |
| `none` | мест нет | «Мест нет» |

### 1.5. Фото нового тура

Взять кадр из поста-анонса: самый общий и узнаваемый — вид города, крепость, горы.
Не еду крупным планом и не людей спиной.

- обрезать по центру в пропорции 3:2, привести к 480×320, JPEG, до ~80 КБ;
- положить в `assets/photos/tour-<slug>.jpg`;
- заполнить `photoAlt`: что на снимке, одной фразой, без «фото» и «изображение».

Инструмента для обработки картинок в окружении нет или не получилось — поставить
`"photo": null`, `"photoAlt": null` и написать в отчёте «нужно фото для `<slug>`».
Сайт покажет мягкую заливку, вёрстка не сломается.

### 1.6. Убрать прошедшие

Тур с `endsOn` раньше сегодняшней даты удалить из массива. Сборщик о таких
предупреждает при запуске — это подсказка, а не ошибка.

## 2. Журнал

1. Открыть `https://www.threads.com/@_slow_travel`, взять три последних поста.
2. Для каждого записать в `data/journal.json`:

   | Поле | Как заполнять |
   |------|---------------|
   | `slug` | латиницей по теме поста, kebab-case |
   | `tag` | одно-два слова: страна, город или тема («Сербия», «Архитектура») |
   | `date` | `YYYY-MM-DD` |
   | `title` | 3–6 слов, без эмодзи, не копия первой строки поста |
   | `text` | пересказ до 280 знаков, тон сохранить, эмодзи убрать |
   | `post` | прямая ссылка вида `https://www.threads.com/@_slow_travel/post/<code>` |

3. Ссылка обязана вести на **пост**, а не на профиль. Не удалось достать код поста —
   запись не трогать, оставить прежнюю.
4. Всегда ровно три записи, от новых к старым.

## 3. Сборка и проверка

```bash
node scripts/build.mjs        # перегенерировать блоки в index.html
node scripts/build.mjs --check # убедиться, что данные валидны и HTML собран
```

Скрипт сам проверяет формат, длину текстов, статусы и что файлы фото существуют.
Упал — **не коммитить**, разобраться или сообщить.

Дополнительно перед коммитом: все `post` из обоих файлов должны отдавать HTTP 200.

## 4. Публикация

Один коммит в `main` и пуш. Без веток и pull request'ов.

Сообщение коммита — по сути изменений, например:

```
chore: Босния 3 → 1 место, Джердап закрыт
```

Если менялся и журнал:

```
chore: обновить места в турах и записи журнала
```

Дальше GitHub Pages передеплоятся сами. Дождаться статуса `built` и проверить,
что `https://citizen-of-makondo.github.io/slow-travel/` отдаёт 200. Если деплой
упал — сказать об этом в отчёте.

Коммитить только то, что меняется по этой инструкции: `data/*.json`, `index.html`
и — если добавили новый тур — файл `assets/photos/tour-<slug>.jpg`. Никаких других
файлов в коммите быть не должно.

## 5. Отчёт

Всегда, даже когда ничего не изменилось. Что должно быть в отчёте:

- **что просмотрено**: диапазон id постов канала и сколько анонсов туров распознано;
- **пост «Информация по местам»**: найден (id, дата) или отсутствует — и то и другое
  нормально, но сказать надо явно;
- построчно, что изменилось: `Босния: 3 → 1 место`, `добавлен тур Сента (24 октября)`;
- хеш коммита и что деплой прошёл;
- что требует рук: нужны фото, не распознан статус, тур под вопросом.

Отчёт без первой строки — признак того, что разбор сломался, даже если он
заканчивается словами «изменений нет».
